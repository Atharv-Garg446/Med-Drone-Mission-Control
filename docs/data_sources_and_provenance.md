# Data Sources, Contracts, and Provenance Classification

## 1. Strict Provenance Taxonomy

Every external, cached, simulated, or synthetic data input in Med-Drone Mission Control carries an explicit `SourceClassification` tag (`airspace_provider.py` and `gdacs_provider.py`). No local fixture or visual map layer is ever labeled as live or official regulatory clearance.

| Classification Enum | Meaning | Modules Using This Tag |
| :--- | :--- | :--- |
| `LIVE_EXTERNAL` | Retrieved over the network during the current run from a live public API, validated against its schema, and within its freshness window. | `GDACSProvider.fetch()` (`gdacs_provider.py`) |
| `OFFICIAL_API_VALIDATION` | Contract-verified against an official government/regulatory OpenAPI specification (`digitalsky_interactive_maps_api_v1.0.yml`). Reports `official_clearance=True` **only** when authenticated with a real pilot token (`x-auth`). | `DigitalSkyIntersectionChecker` (`airspace_provider.py`) |
| `MAP_VISUALIZATION_ONLY` | Browser/UI vector-tile overlay that provides human situational awareness but no machine-readable polygon export or legal route clearance. | `MapplsAirspaceLayerSpec` (`airspace_provider.py`) |
| `SIMULATED_SENSOR` | Generated by a physics/geometry raycaster inside the simulator (`AP_Proximity_SITL` `PRX1_TYPE=10` in ArduPilot C++) observing world geometry. | `MissionRunner.step()` (`sim_sensor_proximity_observation`), `SyntheticCameraSource` |
| `CACHED` | Previously retrieved from a live external feed and served from memory or disk cache (`output/gdacs_cache_latest.json`) with `stale=True` during a network outage. | `CachedGDACSProvider`, `CachedAirspaceProvider` |
| `SYNTHETIC_FIXTURE` | Deterministic scenario polygons, 4D pop-up TFR test zones, and local stop site-suitability dictionaries created for reproducible testing. | `ScenarioProvider`, `GeoJSONFileProvider`, `TFR_POPUP_4D_01` |

## 2. Live External Disaster Feed — GDACS (`gdacs_provider.py`)

### 2.1 Verified API Contract
- **Search Endpoint:** `GET https://www.gdacs.org/gdacsapi/api/Events/geteventlist/SEARCH?eventlist=FL,EQ,TC`
- **Polygon Footprint Endpoint:** `GET https://www.gdacs.org/gdacsapi/api/polygons/getgeometry?eventtype=<type>&eventid=<id>&episodeid=<ep>`
- **Local OpenAPI Reference:** [`docs/external_specs/gdacs_openapi_v1.json`](file:///Users/mahigarg/Documents/Drone%20Shit/drone_medical_router/docs/external_specs/gdacs_openapi_v1.json)
- **Response Behaviour:**
  - Returns HTTP `200` with a GeoJSON `FeatureCollection` when matching alerts exist.
  - Returns HTTP `204 No Content` (empty body) when no events match the filter criteria.
  - Each `Feature` contains `Point` centroid coordinates (`[lon, lat]`), `bbox`, `eventtype` (`FL`, `EQ`, `TC`, `VO`, `DR`, `WF`), `eventid`, `episodeid`, `alertlevel` (`Green`, `Orange`, `Red`), `alertscore`, `fromdate`, `todate`, `iscurrent`, and `url.geometry`.
- **Deduplication & Expiry:**
  - `parse_gdacs_feature_collection()` deduplicates multi-episode records by `(eventtype, eventid)`, retaining the highest `episodeid` / latest `datemodified`.
  - Expired alerts (`todate < now` and `iscurrent == False`) are filtered out by default (`include_expired=False`) and counted in `GDACSSnapshot.expired_filtered`.
- **Outage & Staleness Handling:**
  - `CachedGDACSProvider` persists live snapshots to `output/gdacs_cache_latest.json`.
  - If a network outage occurs, it serves the cached snapshot with `provenance = "CACHED"` and `stale = True` up to `max_age_s` (default 6 hours), after which it raises `GDACSDataStale`.

### 2.2 Mandatory Attribution & Scope Boundary
Every `GDACSEvent` and `GDACSSnapshot` includes:
- **Mandatory Attribution:** `"Global Disaster Awareness and Coordination System, GDACS."`
- **Explicit Scope Disclaimer:** *"GDACS provides macro-level disaster alert centroids, bounding boxes, and hazard footprints for situational awareness and mission prioritization. It does NOT provide street-level flood depth, building collapse geometry, or micro-scale landing pad clearance, and is NOT an aviation airspace authority."*

## 3. Indian Airspace Validation — DigitalSky & Mappls (`airspace_provider.py`)

### 3.1 Official DigitalSky OpenAPI 3.0 Specification
- **Retrieved Spec:** `https://digitalsky.aai.aero/Interactive-Maps-API-Swagger-Documentation-v1.0.yml`
- **Local Copy:** [`docs/external_specs/digitalsky_interactive_maps_api_v1.0.yml`](file:///Users/mahigarg/Documents/Drone%20Shit/drone_medical_router/docs/external_specs/digitalsky_interactive_maps_api_v1.0.yml)
- **Actual Endpoint:** `POST https://digitalsky.dgca.gov.in/digital-sky/flightplan/validate/airspace`
- **Required Request Headers:**
  - `X-API-VERSION: 1`
  - `source: med-drone-mission-control`
  - `x-auth: <JWT pilot authentication token>`
  - `x-correlation-id: <UUIDv1>`
- **Request Body (`FlightPlanAreaValidateRequest`):**
  - `maxAltitude`: float in feet (`maximum: 400`, i.e., `121.92 m AGL` Green-zone ceiling)
  - `minAltitude`: float in feet (`>= 0`)
  - `startDateTime`, `endDateTime`: ISO-8601 UTC timestamps
  - `geom`: Base64-encoded RFC 7946 GeoJSON `FeatureCollection` containing the closed `[lon, lat]` flight corridor polygon
  - `isCircle`: boolean (`false` for polygon corridors)
- **Authentication Gate & Honesty Policy:**
  - Obtaining an `x-auth` token requires a registered DigitalSky pilot/operator account (`POST /api/authenticate`).
  - When `DIGITALSKY_AUTH_TOKEN` / `DIGITALSKY_TOKEN` is not set in the environment, `DigitalSkyIntersectionChecker` validates the request payload against the OpenAPI 3.0 constraints (`maxAltitude <= 400 ft`, closed GeoJSON polygon, base64 encoding) and returns `checked = False`, `official_clearance = False`, `status = "UNAUTHORISED_NO_PILOT_TOKEN"`.

### 3.2 Mappls Airspace Layers (`MapplsAirspaceLayerSpec`)
- **Verified Documentation:** `https://developer.mappls.com/mapping/air-space/`
- **Technical Finding:** Mappls exposes a JavaScript map overlay (`mappls.airspaceLayer({ map, layers })`) with four named visual layers (`coastal_area_india_region_25km`, `airport_region_radius_8_to_12_km_yellow`, `airport_region_radius_5_to_8_km`, `airport_region_radius_0_to_5_km`). It does **not** expose a REST API for downloading raw polygon coordinates.
- **Classification:** `SourceClassification.MAP_VISUALIZATION_ONLY` (`supports_polygon_export = False`, `supports_autonomous_route_clearance = False`).

### 3.3 Investigation of Alternative Indian Aviation & Airspace Data Sources
We audited publicly reachable Indian aviation and aeronautical data sources to determine whether an open, machine-readable, authoritative polygon feed exists outside DigitalSky:
1. **Airports Authority of India (AAI) AIM India eAIP (`https://aim-india.aai.aero`)**:
   - Publishes India's official Aeronautical Information Publication (`eAIP`), including Aerodrome (`AD`) coordinates and `ENR 5.1` Prohibited (`VIP`), Restricted (`VIR`), and Danger (`VID`) airspace tables.
   - **Format & Limitation**: Published solely as human-readable HTML/PDF amendment packages with DMS coordinate text tables—there is **no public unauthenticated REST/GeoJSON/AIXM 5.1 API** for automated UAS polygon ingestion, and UAS Drone Rules 2021 Green/Yellow/Red airport corridors (`5 km / 8 km / 12 km` buffers) are defined exclusively on DigitalSky rather than in `ENR 5.1`.
2. **Official Indian NOTAMs & ICAO APIs**:
   - Official machine-readable NOTAM feeds require restricted AFTN/AMHS institutional access or paid ICAO API subscriptions; no free public unauthenticated JSON NOTAM endpoint exists for Indian FIRs (`VIDF`, `VABB`, `VECC`, `VOMF`).
3. **OpenAIP (`https://www.openaip.net`)**:
   - Provides community-contributed aeronautical airspace JSON/GeoJSON via a key-gated REST API (`x-openaip-api-key`), but explicitly disclaims operational or regulatory authority and lacks Indian DGCA UAS Red/Yellow drone zone boundaries.
4. **Resulting Engineering Architecture**:
   - Authoritative UAS corridor validation uses `DigitalSkyIntersectionChecker` (`OFFICIAL_API_VALIDATION`, full-route polyline check, honestly returning `checked = False, official_clearance = False` without a DGCA pilot `x-auth` JWT).
   - Arbitrary external GeoJSON airspace datasets (e.g., manually digitized eAIP polygons or operator-supplied corridors) can be ingested offline via `GeoJSONFileProvider` (`airspace_provider.py`).
   - Built-in Jaipur/Chennai airport and pop-up TFR polygons carry `SourceClassification.SYNTHETIC_FIXTURE` so synthetic test data is never misrepresented as live regulatory clearance.
